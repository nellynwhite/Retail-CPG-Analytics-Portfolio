Star schema overview

Fact_WeeklySales

FK week_id, store_id, item_id · units and sales TY/LY, gross margin, is_on_promo, promo_lift_units · 26,000 rows

Fact_Inventory

FK week_id, store_id, item_id · on-hand BOP/EOP, receipts, lost_sales_units, in_stock_flag, weeks_of_supply, fill_rate · 26,000 rows

Fact_PromoCalendar

FK week_id, item_id · incremental_units, lift_pct, est_trade_spend, roi_estimate · 520 rows

Fact_SupplyChain

FK week_id, item_id, supplier_id · otif flags, on_time, in_full, shortage_units, fine exposure, MAPE · 520 PO lines

Dim_Date

Composite key (week_id + fiscal_year_label) · NRF fiscal, quarter, season, holiday week

Dim_Store / Dim_Item

600 stores (region, format, tier); 10 items (category, fineline, supplier, base price)

Dim_Supplier

5 suppliers with lead time and contractual OTIF target

Dim_PromoMechanism / Dim_Category / Dim_Fineline

Promo type, category and sub-category groupings

Relationships
All dimensions resolve 1:Many to the facts with single direction cross filter. Dim_Date joins all four facts on the composite date key; Dim_Store joins the two store-grain facts; Dim_Item joins all four.
Model design decisions

Composite date key

Dim_Date holds both TY and LY weeks, so week_id alone was not unique and broke 1:Many. A composite of week_id and fiscal_year_label makes every row addressable. Result: correct filter propagation to all four facts.

TY and LY as columns

Walmart's 52-week NRF calendar makes standard time intelligence unreliable. TY and LY values are stored in the same fact row, pre-aligned by fiscal week. Result: YoY is simple column subtraction, no DATEADD or SAMEPERIODLASTYEAR edge cases.

Import over DirectQuery

At 52K total fact rows the model compresses under 10MB and renders in under one second. SQL views are structured so a DirectQuery migration is available at production volume.

Boolean filters use = TRUE()

CALCULATE treats a bare boolean column as a table filter. All 14 measures filtering is_on_promo or in_stock_flag use explicit = TRUE() so filter context is unambiguous.

Core SQL view (semantic layer)
-- vw_SalesDrivers: one row per week x store x item, all dimensions joined. -- Backs the Sales Overview and Weekly Performance pages. CREATE OR REPLACE VIEW vw_SalesDrivers AS SELECT d.week_id, d.fiscal_year_label, d.quarter_id, d.season, s.store_id, s.region, s.store_format, s.volume_tier, i.item_id, i.item_description, c.category_name, sup.supplier_name, fs.units_ty, fs.sales_dollars_ty, fs.gross_margin_ty, fs.sell_price_ty, fs.units_ly, fs.sales_dollars_ly, fs.gross_margin_ly, fs.sell_price_ly, fs.dollar_chg_yoy, fs.pct_chg_yoy, fs.is_on_promo, fs.promo_lift_units, ROUND(fs.gross_margin_ty / NULLIF(fs.sales_dollars_ty, 0), 4) AS gm_rate_ty FROM Fact_WeeklySales fs JOIN Dim_Date d ON fs.week_id = d.week_id JOIN Dim_Store s ON fs.store_id = s.store_id JOIN Dim_Item i ON fs.item_id = i.item_id JOIN Dim_Category c ON i.category_id = c.category_id JOIN Dim_Supplier sup ON i.supplier_id = sup.supplier_id LEFT JOIN Dim_PromoMechanism pm ON fs.promo_mechanism_id = pm.promo_mechanism_id;
Price vs. volume decomposition
-- Splits a category's YoY dollar change into volume, price and mix effects. WITH base AS ( SELECT category_name, SUM(dollar_chg_yoy) AS total_dollar_chg, SUM((units_ty - units_ly) * sell_price_ly) AS volume_effect, SUM(units_ly * (sell_price_ty - sell_price_ly)) AS price_effect FROM vw_SalesDrivers GROUP BY category_name ) SELECT *, total_dollar_chg - volume_effect - price_effect AS mix_effect FROM base ORDER BY total_dollar_chg DESC;
Finding from this query
Across all five categories the volume effect dominates the price effect, confirming the +6.8% portfolio gain is unit driven rather than price driven.
Core DAX measures
Measure Expression Business use
Total Sales TY SUM(Fact_WeeklySales[sales_dollars_ty]) Primary revenue KPI ($32.23M)
Sales % Chg YoY DIVIDE([Total Sales TY]-[Total Sales LY], [Total Sales LY], 0) YoY growth (+6.8%); DIVIDE guards zero LY
Gross Margin % DIVIDE([Gross Margin TY], [Total Sales TY], 0) Profitability (28.0%)
Promo Sales TY CALCULATE([Total Sales TY], Fact_WeeklySales[is_on_promo] = TRUE()) Promo mix (26.8% of sales)
In-Stock Rate AVERAGE(Fact_Inventory[in_stock_flag]) Availability vs. 95% target (88.9%)
Lost Sales $ SUMX(Fact_Inventory, [lost_sales_units] * RELATED(Dim_Item[base_price])) Quantified stockout cost ($4.1M)
Avg WOS AVERAGE(Fact_Inventory[weeks_of_supply]) Forward cover vs. 2.0 floor (1.4)
OTIF Compliance AVERAGE(Fact_SupplyChain[otif_flag]) On-time and in-full delivery (55.0%)
OTIF Fine Exposure $ SUMX(Fact_SupplyChain, [shortage_units] * [fine_rate] when eligible) Penalty exposure ($304K)
